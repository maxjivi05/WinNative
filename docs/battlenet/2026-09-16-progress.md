# Battle.net continuation — 2026-09-16

## Delivered

- Shared-directory binding preserves empty directories under unique `*.winnative-preserved-*` names instead of deleting them. Foreign links in destination parents or shared targets, including dangling links, are rejected. The existing process-wide binding lock still serializes binds.
- Installer responses must have an executable header before an atomic write begins. Downloads use the real shared directory, and linked output files, atomic sidecars and parent directories are rejected. An invalid response no longer removes an existing installer. Credential cleanup also rejects linked parent directories.
- `Battlenet` uses the existing store detail header and its pane-navigation update menu. Update checks run on the IO dispatcher and compare the active product's local `.build.info` build key with Blizzard's regional version service.
- The Rust JNI library uses HTTPS without redirects, bounded responses, request timeouts, strict product/region validation and defensive PSV parsing. Its errors contain no HTTP bodies or credentials. The included CLI performs the same public build lookup.

This is an update-check and preservation milestone, not a completed Rust game downloader. Installation, repair, pause/resume/cancel and authenticated launch still use the existing official-client path. No unsupported control is presented as implemented. The `download-size` field in a build configuration is the size of the download manifest itself, not the size of the game.

## Reproduce the Rust library

Ordinary APK builds use the checked-in `app/src/main/jniLibs/arm64-v8a/libwn_battlenet.so`, following the repository's prebuilt-library convention. Rebuilding it requires Rust 1.88 or newer, the `aarch64-linux-android` target, and Android NDK 27.3.13750724 on Linux:

```sh
rustup target add aarch64-linux-android
cargo test --locked --manifest-path app/src/main/rust/battlenet/Cargo.toml
cargo clippy --locked --manifest-path app/src/main/rust/battlenet/Cargo.toml --all-targets -- -D warnings
ANDROID_HOME=/path/to/sdk app/src/main/rust/battlenet/build-android.sh
cargo run --locked --manifest-path app/src/main/rust/battlenet/Cargo.toml --bin battlenet-metadata -- wow us
```

The native library targets the Android host ABI, not a Wine guest ABI. It contains no x86/ARM64EC Proton assumptions. That does not establish game compatibility on either Proton runtime.

## Agent 9775 research

Agent executable SHA-256: `72a468b7622db394152d2b722d2011a7cdec7a0600cc9c9b106286f03d01cd76`.

Ghidra 11.3.1 analyzed the official Agent. These are evidence addresses for this binary, not hooks:

| Address | Observation |
| --- | --- |
| `0x0041fc13` | Parses `--internalclienttools`, port and lifecycle options |
| `0x004308e0` | Agent response construction references authorization |
| `0x0043a79e`, `0x004320dd`, `0x00437e3c` | Operation handlers parse a `cancel` property |
| `0x004e2386` | Update handling emits `pause_update` telemetry with pause/resume values |

A host-side unauthenticated `GET /agent` returned 401. A Windows WinHTTP probe running in the isolated Wine prefix with Agent's internal-client mode obtained HTTP 200 and authorization. An authenticated host request then succeeded. This establishes the local Agent transport handshake, not a Blizzard account session. No signature/authentication checks were patched.

Using the flow demonstrated by [Battle.Net-Installer](https://github.com/barncastle/Battle.Net-Installer), `POST /install` for `s1` returned HTTP 201 and `/install/s1`. The unfinalized form reported `required_space=6900000000`; `required_space_info.size` remained zero. Posting a locale/path selection with `finalized=false` returned authentication error `5002`. The declared space requirement therefore is not evidence of a completed, locale-specific download-size calculation. No game download was finalized. `PUT /install/s1` returned 405; the product form uses POST.

Blizzard's installer subsequently installed desktop client 2.52.11.17778 in an isolated desktop Wine prefix. Its client, Agent and user configuration directories were moved into a sibling shared store and symlinked back, without removing directories. This host installation has no real account session. It is not embedded in the APK or installed into an Android Proton container.

Research files and the roughly 1.5 GB client remain outside Git under the new work directory. Live/local authorization responses must not be committed or included in diagnostics.

## Remaining work

A full replacement requires an account-authenticated Agent lifecycle (or a complete direct TACT/CASC installation writer), accurate selected-content planning, foreground download service ownership, persistent transfer state, tested pause/resume/cancel semantics that preserve files, repair verification and authenticated launch validation. Both Android Proton architectures need device tests. The local HTTP handshake alone does not supply account entitlements, game keys or game-launch credentials.
