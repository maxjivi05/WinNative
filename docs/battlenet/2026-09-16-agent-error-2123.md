# Battle.net Agent error 2123

## Failure

Agent 9775 accepts the `wow_classic` launch request, queues an update, and then reports:

```text
Unable to create TACT container folder 'G:/World of Warcraft Classic-a918d337491e3ffe961373f1a48df50c/Data/'
Build marked non-playable for wow_classic: Permissions check failure (2123)
```

The game data is present and fully verified. `Data` is also present. Agent nevertheless leaves both launch paths empty and reports the product as non-playable, so the desktop client displays Locate or Game Not Found.

## Root cause

The `G:` drive maps directly to Android shared storage under `/storage/emulated/0`. On the device this is `/dev/fuse`. It exposes the game directory with synthesized ownership and mode information, and `listxattr` fails with `EOPNOTSUPP`.

The app-private Battle.net tree is on `/data/user/0`. It supports extended attributes and contains Wine's `user.wine.sd` security descriptor. Agent works there because Wine can persist and read the Windows ACL it applies while creating a TACT container.

Ghidra analysis of Agent 9775 confirms the order:

1. The update path creates the TACT container directory before content or executable validation.
2. A nonzero result immediately emits the TACT container error.
3. The permission result marks the build non-playable and clears launchability.

The Agent configuration exposes `version_operation_disables.disable_permission_check`, but the live value is `false`. More importantly, the TACT container create runs before the later version checks, so changing the product database or only disabling the final permission check does not repair the underlying filesystem operation.

The previous private-path symlink approach cannot solve this. Agent explicitly detects a symlink in a secure root and rejects it. A normal Wine drive mapped directly to Shared storage avoids that check but still exposes FUSE semantics.

## Required fix

Add an Android shared-storage security-descriptor backend to the WinNative Proton/Wine components used by Battle.net, for both x86-64 and ARM64EC.

For a drive backed by Android emulated storage, Wine must emulate Windows security descriptors without requiring the target filesystem to persist Unix ownership, mode changes, ACLs, or `user.*` extended attributes. Store descriptor metadata in an app-private database keyed by the drive and normalized path, or synthesize the permissive descriptor used by this permissionless filesystem. `SetSecurityInfo` and `GetSecurityInfo` must agree, and directory creation must treat the unsupported host ACL operation as successfully represented by the compatibility backend.

The metadata store should remain outside the Shared game tree, use atomic replacement, serialize updates per path, and never follow or delete game-directory symlinks. Rename and move operations need to migrate the metadata key. Uninstall and cancel must remove only records owned by the exact game registration.

Ship the change in both Battle.net Proton variants and select those component versions for the Battle.net container. Changing only Kotlin registration data, `.product.db`, `.build.info`, or the Rust downloader cannot make Agent's Windows ACL operation succeed.

## Rejected workarounds

- Copying the 21.38 GiB installation into app-private storage would work around FUSE but duplicates the game and stops Shared from being the canonical installation.
- A symlink from app-private storage is rejected by Agent's secure-root check.
- A bind mount or an ext4 image would need mount privileges that the application process does not have.
- Editing Agent's cached configuration is hash-sensitive, version-specific, and still does not repair the initial TACT directory operation.
- Launching `WoWClassic.exe` directly does not replace Battle.net's authenticated launch session.

## Validation

Before retesting the complete game, add a small Windows probe that runs inside each Proton variant against the Shared drive:

1. Create and reopen a directory.
2. Apply the same inheritable DACL through `SetNamedSecurityInfoW`.
3. Read it through `GetNamedSecurityInfoW` and compare the effective entries.
4. Rename the directory and confirm that the descriptor follows it.
5. Exercise concurrent readers and writers under Thread Sanitizer or an equivalent host test.

Then register the existing WoW Classic folder without redownloading it. Agent must report a nonempty `binary_launch_path64`, `installed=true`, and `playable=true`. Check for updates and Verify Files must complete against the same Shared path. Finally, launch from the Library card and confirm that Battle.net selects WoW Classic and starts the game with the saved account session.
